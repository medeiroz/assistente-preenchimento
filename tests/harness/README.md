# Harness de componentes

Página local com Vue 2.7 + vue-multiselect 2.1 reais (builds UMD de `node_modules`, sem bundler) imitando o modal de NFS-e da CE. Dados fictícios.

- Debug manual: `npm run harness` (imprime a URL).
- Query string: `?preset=loaded` (abre já carregado), `?close=class` (fechar só remove `is-active`).
- API: `window.__harness.{getState, open(preset?), close, hideViaClass}`; `window.__emitted` vira `true` ao clicar em "Emitir NFS-e".
- Imita o site real: com o modal aberto, Escape (keydown ou keyup) no `document` abre o diálogo "Deseja cancelar a emissão da nota?" (`.eui-confirm-wrapper`, botões "Voltar" / "Sim, cancelar"). "Sim, cancelar" fecha o modal e seta `window.__cancelled = true`; "Voltar" só fecha o diálogo. `window.__escapeCount` conta os Escape que chegaram ao document. Os adaptadores nunca podem disparar teclado borbulhante: os testes e2e exigem `__escapeCount === 0`.
- Seção "Outros campos" (`#outros-campos`, dentro do modal, fora dos `.eui-modal-body > .eui-field` diretos): select nativo "Distribuidora", radios "Tipo de conta" (Residencial/Comercial; state guarda o `value` `residencial`/`comercial`), checkbox "Débito automático", toggle de botões "Tipo de pessoa" (Física ativo por padrão, `is-filled`/`is-outlined`), `input[type=date]` "Vencimento" e `input.eui-input-datepicker` "Data de competência" (texto DD/MM/YYYY). Todos com v-model e expostos em `getState()` (`distribuidora`, `tipoConta`, `debitoAuto`, `tipoPessoa`, `vencimento`, `competencia`).
- Servidor: `tests/e2e/harness-server.ts`; testes: `npx playwright test tests/e2e/harness.spec.ts`.
- Select "Operação de uso ou consumo pessoal": imita o "×" do select `is-clearable` da CE via slot `clear` do vue-multiselect (`<div class="multiselect__clear">`, só aparece com valor; `mousedown` zera o v-model). Os demais multiselects não têm o botão (limpar = clicar na opção selecionada).
- Assistente fictício de 3 passos (`/wizard/step1.html`): passo 1 navega por completo (form GET) para `step2.html`; o passo 2 troca o DOM para o passo 3 via `history.pushState` (SPA). Inclui um campo de senha, que a gravação nunca pode registrar. Usado por `tests/e2e/recorder.spec.ts`.
- Campos "CPF do tomador" (`#doc-cpf`, máscara 000.000.000-00) e "Nome do tomador" (`#doc-nome`, desabilitado): a "busca" só habilita o nome depois de 11 dígitos digitados com teclas reais (`window.__docKeys` conta os keydown no CPF; escrita programática não habilita). Usados por `tests/e2e/typing.spec.ts`.
- Página `/shadow.html` (Shadow DOM, custom elements nativos): (a) rótulo fora e input no shadow, (b) rótulo e input dentro, (c) shadow aninhado em 2 níveis, (d) shadow `closed` (deve ser ignorado), (e) campo inserido no shadow após 500 ms, (f) input sem rótulo (a captura gera `host >>> interno`). Reusa o contêiner do preset e2e; `window.__shadowEvents` lista os `input`/`change` que chegaram ao document. Usada por `tests/e2e/shadow.spec.ts`.
- Página `/frames.html` (iframes): (a) `#same` (mesma origem, `/frame-form.html`), (b) `#srcdoc` (herda a origem do pai) e (c) `#cross` (outra origem: `http://localhost:<mesma porta>`). Cada iframe tem o formulário `form.alvo` com o campo rotulado "Nome do iframe" (`#nome`). A página de topo não tem esse formulário. Usada por `tests/e2e/frames.spec.ts`.
